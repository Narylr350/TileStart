# TileStart UI / UX 实现状态

> 最近审计：2026-08-04
>
> 状态依据：当前 `main` 源码、自动测试和已保存的实机验收记录。
>
> 原版截图、布局导出、符号和逆向过程保存在仓库外的私有研究档案中，不随公共源码分发。

## 1. 产品边界

- 主界面布局、信息架构和操作习惯始终按 Windows 10 扩展开始菜单设计。
- Win10 主题以 Windows 10 19045 原版开始菜单为外观精确校准目标。
- Win11 主题复用同一套 Win10 主布局，只替换字体、材质、颜色、描边、圆角和控件状态。
- 不引入 Win11 原生开始菜单的 Pinned、Recommended、分类或分页布局。
- 动画可以由 TileStart 独立设计，不要求逐帧复制 StartUI 私有实现，但必须状态完整、视觉协调、符合直觉并响应 Windows 动画设置。

## 2. 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现 | 生产路径已接入，具有源码或测试证据 |
| 已实现并验收 | 已实现，且有用户实机视觉或交互验收记录 |
| 部分实现 | 主路径存在，但视觉、边界、实时响应或输入方式不完整 |
| 仅研究 | 已取得原版证据，尚未按该证据接入生产实现 |
| 未实现 | 当前生产代码没有对应行为 |
| 无需实现 | 与当前产品边界冲突，不应列为缺失项 |

## 4. Win10 布局与交互

### 4.1 已实现

- 底部锚定、不覆盖任务栏、无普通标题栏的可调整窗口。
- 顶部、右侧和右上角调整大小，窗口尺寸和工作区列数持久化。
- 多显示器、工作区、任务栏边缘和 Per-Monitor DPI 基础路径。
- 48 DIP 收起导航轨、256 DIP 展开导航轨、48 DIP 导航项。
- 260 DIP All Apps 列、244 DIP 应用项、36 DIP 行高和分组标题。
- 最近添加、应用文件夹、字母分组和字母索引。
- 48 DIP 字母单元、20 DIP 字号和双视图 SemanticZoom。
- 48 DIP 基础磁贴单元、4 DIP 间隙、52 DIP 步长。
- `1×1`、`2×2`、`4×2`、`4×4` 四种磁贴尺寸。
- 8 单元默认组宽、自定义组宽高跨度、组内碰撞和空位查找。
- `Win10GroupWrapPanel` 二维组布局、窗口宽度变化后的分组换行和纵向滚动。
- 32 DIP 组标题、空名称组、临时编辑框和整组拖动。
- 28 DIP 磁贴 branding 区，默认标题位于左下。
- 磁贴文件夹、3×3 折叠预览和展开内容区。
- Win10 风格右键菜单、子菜单、调整大小和 TileStart 扩展入口。
- 公共设置、磁贴设置和组设置窗口支持工作区约束；标题与操作栏固定，中间内容可收缩或纵向滚动，磁贴设置窄窗口不会产生整页水平滚动。

### 4.2 部分实现或待精确校准

- 主窗口、导航轨、应用列表、磁贴区、文件夹和右键菜单已在 Windows 10 22H2 虚拟机完成当前一轮 Light / Dark 视觉验收；主页面已达到肉眼对照基本一致。
- 尚未为所有 Hover、Pressed、Disabled、空布局和极端窗口尺寸建立成套公开截图证据，后续按实际发现的问题继续校准。
- Acrylic 使用 Win32 AccentPolicy 映射，已经实机验证为可接受近似，但不等同于 UWP AcrylicBrush 的完整合成实现。
- 应用列表图标尺寸与 Shell 高分辨率加载已经接入；StartUI 内部 Logo 类型 raw value 5、资产优先级和全部状态尺寸仍未闭环。
- 键盘焦点只覆盖 Escape、搜索、字母索引返回和组名编辑等局部路径，尚未形成完整方向键、Tab、Enter、Space 和 Menu 键矩阵。
- 鼠标拖动路径完整；触摸、笔、长按和惯性手势尚未形成独立输入路径。
- 高对比度会禁用 Acrylic，托盘有颜色回退；主界面没有完整 High Contrast 主题和无障碍状态覆盖。

### 4.3 明确未实现或行为不符合目标

- 当前直接输入会显示 TileStart 自己的 36 DIP 搜索框并过滤应用列表，没有转交 Windows Search。
- All Apps 的普通字母输入没有实现 Win10 的 type-to-jump。
- 应用列表、磁贴区和导航轨之间的完整键盘方向导航没有实现。
- Narrator / AutomationPeer、文本缩放和完整高对比度主题没有实现。

## 5. Win11 视觉主题

### 5.1 已实现

- Win10 与 Win11 主题共用 `MainWindow.xaml` 和同一套 Win10 布局。
- Win11 使用 Segoe UI Variable Text / Display。
- 提供 Win11 深色和浅色文字层级、表面色、Subtle Fill、描边和错误/警告/成功色。
- 普通控件使用 4 DIP 圆角，弹窗、菜单和卡片使用 8 DIP 圆角。
- 磁贴使用 4 DIP 圆角、弱半透明表面和无常驻描边，保留 Win10 磁贴尺寸、分组和信息层级。
- Win11 窗口使用 DWM 圆角，Win10 窗口明确关闭 DWM 圆角。
- Win11 Acrylic 使用壁纸派生 `StartColorMenu` 色调；透明关闭或高对比度时使用不透明回退。
- Win11 顶层菜单和子菜单使用独立 Popup Acrylic 与 DWM 圆角；公共设置、编辑和信息窗口使用 DWM Transient Acrylic，并将系统 backdrop 扩展到完整客户区。
- 公共对话框具有响应系统动画设置的淡入位移和关闭过渡，导航展开底板只在远离屏幕边缘的一侧使用圆角。
- SharedStyles 已覆盖 Button、TextBox、CheckBox、ComboBox、Slider、Expander、ToolTip、ContextMenu、MenuItem、Dialog、Card 以及组设置应用条目等常用控件。

### 5.2 待补齐

- 当前一轮已覆盖主窗口、导航、应用列表、磁贴、菜单、公共对话框和主要二级编辑控件；不再为了覆盖率继续主动扩张。
- 少见控件状态、极端布局和 High Contrast 仍可能存在未被当前实机路径触发的遗漏，后续只按明确复现修复。
- Win11 主题是 TileStart 对 Win10 UI / UX 的 Fluent 化设计，不宣称复刻 Win11 原生开始菜单。

### 5.3 无需实现

- Win11 Pinned / Recommended 布局。
- Win11 原生分类、分页和推荐内容。
- 为匹配 Win11 原生开始菜单而移除磁贴、应用列表或 Win10 分组布局。

## 6. Windows 设置响应

| 设置 | 状态 | 当前行为 |
| --- | --- | --- |
| 应用浅色/深色模式 | 已实现 | `System` 模式检测变化后重启 TileStart |
| 动画效果 | 已实现 | 主要动画路径读取 `SystemParameters.ClientAreaAnimation` |
| 透明效果 | 已实现 | 每次显示菜单重新读取 `EnableTransparency` |
| 高对比度 | 部分实现 | 禁用 Acrylic，托盘回退；主界面没有完整高对比度主题 |
| 系统强调色 | 已实现 | 启动时读取 `AccentColorMenu` / `AccentPalette`；系统颜色变化触发 TileStart 自动重启，使磁贴、菜单状态和主题资源统一刷新 |
| 壁纸派生开始菜单色 | 已实现 | Win11 Acrylic 使用 `StartColorMenu`，主题重载同步默认磁贴表面；Win10 强调色开关和实时缩放回退已有专项修复 |
| 鼠标 Hover 时间 | 已实现 | 导航轨展开使用系统值 |
| 鼠标滚轮行数 | 已实现 | 平滑滚动使用系统值 |
| 系统拖动阈值 | 已实现 | 使用 Windows 最小水平/垂直拖动距离 |

## 7. 性能与响应性

- 应用与磁贴图标批量加载已经放到低优先级后台线程，不在菜单显示路径同步枚举完整应用列表。
- 2026-08-04 Rider Monitoring 与运行日志交叉审计确认：95 个磁贴对 333 个应用进行完整视觉恢复时，当前身份匹配存在 `O(磁贴数 × 应用数)` 重复计算，第二轮视觉恢复曾耗时 34.7–55.9 秒。该工作主要在后台线程执行，不等同于 UI 冻结，但会延迟最终图标状态并持续占用 Shell/COM 与文件系统资源。
- 磁贴设置预览在滑块变化时仍可能同步重新读取图片或 Shell 图标，是当前可直接影响交互手感的 UI 线程热点。
- `ShowTileSettingsDialog` 的持续时间包含整个模态窗口停留过程，不能作为窗口打开耗时；设置启动性能应以构造完成、`ContentRendered` 和首帧稳定为边界。

## 8. 当前优先级

1. 将完整磁贴视觉恢复改为单次身份索引，消除重复快捷方式 COM 解析；同时避免设置滑块每帧重复解码图像。
2. 将直接输入改为 Windows Search 转交，并补 All Apps 字母 type-to-jump。
3. 补齐键盘焦点和方向导航。
4. 扩大 Win10 / Win11 Shell、DPI、任务栏位置和极端布局回归。
5. 补齐 High Contrast、Narrator、文本缩放、触摸和笔输入等可访问性路径。
6. 视觉主题进入维护阶段，只修复实际使用中发现的明确问题，不重写已经验收的主界面和动画。
